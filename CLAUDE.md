# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Personal portfolio for Zariff Danial, built with Vite 8 and React 19 and deployed to Vercel at https://zariffdanial.vercel.app/. All content lives in the locale files and a few data modules; there is no CMS. The design system is documented in [docs/DESIGN.md](docs/DESIGN.md).

## Commands

- `npm install` — install dependencies (`.npmrc` sets `legacy-peer-deps`; the eslint-plugin-react and eslint-plugin-jsx-a11y peer ranges stop at ESLint 9 although both run fine on 10)
- `npm run dev` — Vite dev server on http://localhost:3000 (strict port, hot reload)
- `npm run build` — production build to `dist/` (target es2020). Vite does not run ESLint, so a green build says nothing about lint.
- `npm run preview` — serves `dist/` on http://localhost:4173 with SPA fallback; the closest thing to Vercel locally
- `npm run lint` — ESLint over the source tree (tools/, dist/ and build/ are ignored) with the flat config in [eslint.config.mjs](eslint.config.mjs) (@eslint/js, react, react-hooks, jsx-a11y). This is the gate before pushing: it must exit 0 with zero errors and zero warnings. Fix the code rather than disabling rules; the only inline disable is documented next to it.
- `npm test` — vitest, single run (`npm run test:watch` for watch mode). [src/App.test.jsx](src/App.test.jsx) renders the whole app; jsdom shims for `matchMedia`, `IntersectionObserver` and `scrollTo` live in [src/setupTests.js](src/setupTests.js), which also registers the jest-dom matchers. The vitest block lives in [vite.config.mjs](vite.config.mjs).
- `npm run qa` - the browser quality sweep, [tools/qa/sweep.mjs](tools/qa/sweep.mjs). Run `npm run build` first: the script starts `vite preview` on 4173, opens every route (including a 404) in headless Chromium in both themes at 1440 and 390, plus Bahasa Malaysia passes on desktop dark and mobile dark, scrolls each page so the reveals fire, and fails on any console or page error, horizontal overflow, a page without exactly one `h1`, or a serious or critical axe violation (WCAG 2.0 A and AA, 2.1 AA). Full-page screenshots, the axe JSON per page and `report.json` land in `tools/qa/output/` (gitignored). Set `PW_CHANNEL=chrome` locally to use the installed Chrome instead of downloading Playwright's Chromium (otherwise `npx playwright install chromium` once). Without `--serve` the script sweeps a server that is already running (`--url=http://localhost:3000` for the dev server); `--routes=home,about` limits it to a subset. It ignores requests to the third-party contribution calendar API, answers Vercel's edge-injected analytics scripts with an empty script (the preview server has none), and reports without failing on a failed load from another origin such as Google Fonts; a failed load of the site's own files or any script error still fails the page.

Vercel runs `npm run build` on Node 22 (the floor is in `engines` and `.nvmrc`) and serves `dist/`; [vercel.json](vercel.json) pins the Vite preset and output directory, rewrites every non-asset path to `/index.html` so deep links into client-side routes resolve, and marks `/assets/*` immutable. A small `route-html` plugin in [vite.config.mjs](vite.config.mjs) also writes `dist/<route>.html` for about, project, resume, uses, mytax and bestinet, each a copy of `index.html` with that route's title, description, canonical and Open Graph tags taken from `meta.*` in `en.json`; one rewrite per route in vercel.json, listed before the catch-all, serves each at `/<route>` (vite preview does the same by itself), so crawlers and link previews see the right page without running JavaScript. Do not switch on `cleanUrls` instead: it renames `index.html` to `/index` and breaks the catch-all's `/index.html` destination. Add a route in both places when you add an indexable page, with `meta.<key>` and `meta.<key>Desc` in both locale files. The build fails if a tag it swaps is missing from `index.html`. `src/main.jsx` reloads the page on the Vite `preloadError` event, which fires in a tab still open across a redeploy when its chunk names have gone stale.

CI: [.github/workflows/quality.yml](.github/workflows/quality.yml) runs on every push to `main` and every pull request, on Node 22: `npm ci`, `npm run lint`, `npm test`, `npm run build`, then `npm run qa` in Playwright's own Chromium. Any red step fails the job, and `tools/qa/output` is always uploaded as the `qa-screenshots` artifact (kept 14 days) so a failure can be inspected from the screenshots and axe reports. This is the same standard the site was reviewed against; a change that breaks it in either theme, either viewport or in Bahasa Malaysia should not land.

## Architecture

Single-page React 19 app with `react-router-dom` v7 (declarative API: BrowserRouter, Routes, Route, Link, NavLink). Every file that contains JSX has a `.jsx` extension; hooks, data, utils, i18n and CSS keep their names, and imports omit extensions. Entry: [index.html](index.html) at the repo root (the inline theme script, font links, meta tags and JSON-LD live here; files in `public/` are referenced as `/name`) → [src/main.jsx](src/main.jsx) (`createRoot` + `StrictMode`) → [src/App.jsx](src/App.jsx), which lazy-loads each route inside `<main id="main">`, mounts the shared chrome, and gates a 0.7s wordmark preloader. StrictMode double-invokes effects in dev, so every effect (count-ups, observers, timers) must be idempotent.

Routes:
- `/` — [Home.jsx](src/components/Home/Home.jsx): hero (MyTax phone composition), selected work, about teaser with stats, CTA band
- `/about` — [About.jsx](src/components/About/About.jsx) composes twelve self-contained sections in a fixed order; each renders its own `<Section>` and heading
- `/project` — [Projects.jsx](src/components/Projects/Projects.jsx): segmented filter plus a grid of `ProjectCard` (`AnimatePresence mode="popLayout"`)
- `/resume` — [ResumeNew.jsx](src/components/Resume/ResumeNew.jsx) renders the PDF in [src/Assets/](src/Assets/) via `react-pdf` 10; the pdf.js worker is the one bundled with the installed `pdfjs-dist`, resolved with `new URL("pdfjs-dist/build/pdf.worker.min.mjs", import.meta.url)`, so there is no CDN dependency and the versions can never drift
- `/uses` — [Uses.jsx](src/components/Uses.jsx)
- `/mytax` — [MyTaxCaseStudy.jsx](src/components/MyTaxCaseStudy.jsx), English only
- `/bestinet` — [BestinetCaseStudy.jsx](src/components/BestinetCaseStudy.jsx), English only
- anything else — [NotFound.jsx](src/components/NotFound.jsx)

Shared chrome in [src/components/](src/components/): `Navbar.jsx` (desktop links, full-screen mobile menu, theme and language toggles), `Footer.jsx`, `SocialSidebar.jsx`, `ScrollProgress.jsx`, `BackToTop.jsx`, `CustomCursor.jsx`, `ToastContainer.jsx`, `KonamiEgg.jsx`, `ScrollToTop.jsx` (also resolves `#hash` targets on lazy routes), and [ui/Backdrop.jsx](src/components/ui/Backdrop.jsx) (fixed aurora + film grain behind every page).

Primitives in [src/components/ui/](src/components/ui/): `Container`, `Section`, `SectionHeading`, `Button`, `Chip`, `Reveal` / `Stagger` / `StaggerItem` (framer-motion scroll reveals), `PhoneFrame`, `Wordmark`. Import them from `"../ui"`. Shared components: [StoreLinks.jsx](src/components/StoreLinks.jsx) (App Store / Google Play / AppGallery buttons with install counts), [Projects/ProjectCard.jsx](src/components/Projects/ProjectCard.jsx) (used by both Home and Projects) and [StatTile.jsx](src/components/StatTile.jsx) (`StatGrid` + `StatTile`, used by Home and About). The GitHub contribution graph in [About/Github.jsx](src/components/About/Github.jsx) uses `react-github-calendar` 5 (named export): `theme` takes both five-colour palettes and `colorScheme` picks the active one from `ThemeContext`.

Data modules in [src/data/](src/data/): `projects.js` (the project list; copy keys are `projects.<id>_title` and `projects.<id>_desc`), `mytax.js` (store links, press, the MyTax screenshot list), `screenshots.js` (every phone screenshot with its 300px rendition; `register(full, small)` and `srcSetFor()`), `stats.js`. Hooks in [src/hooks/](src/hooks/): `useCountUp`, `useInViewOnce`, `usePageMeta` (title, description, per-route canonical and og:url, optional `noindex`). Utilities in [src/utils/](src/utils/): `formatMonth(iso, lang)` renders `YYYY-MM` dates in the active language.

Contexts: `ThemeContext` (dark by default, persisted in localStorage `theme`, also applied before first paint by an inline script in [index.html](index.html)) and `ToastContext`.

i18n: `react-i18next` with [en.json](src/i18n/locales/en.json) and [ms.json](src/i18n/locales/ms.json). The two files must keep key parity, and every visible string goes through `t()`.

## Styling

No Bootstrap and no `!important` anywhere. Components read design tokens only.
- [tokens.css](src/styles/tokens.css) — every colour, type, spacing, radius, shadow, motion and z-index token; dark values on `:root`, light values under `html[data-theme="light"]`
- [base.css](src/styles/base.css) — reset, typography, focus rings, scrollbar, reduced motion, and the shared classes (`.container`, `.section`, `.eyebrow`, `.section-head`, `.btn`, `.chip`, `.surface`, `.prose`, `.meta-list`, `.phone`, `.wordmark`, `.site-backdrop`)
- [chrome.css](src/styles/chrome.css) — navbar, mobile menu, footer and the fixed elements
- One stylesheet per route (`home.css`, `about.css`, `about-sections.css`, `projects.css`, `resume.css`, `uses.css`, `casestudy.css`, `notfound.css`) plus `project-card.css`, `store-links.css` and `stat-tile.css`, each imported by the component that uses it so it code-splits with the route. Home is imported statically in `App.jsx` (it is the landing route); the others are lazy.

`src/index.css` loads tokens and base; `src/style.css` loads chrome. Fonts (Bricolage Grotesque for display, Inter for body, JetBrains Mono for labels) come from Google Fonts via `index.html`.

## Content edits

- Copy: edit both locale files. Never use em or en dashes in copy; the owner treats them as a tell. Page titles and descriptions live under `meta.*`; store button labels under `store.*`.
- Projects: [src/data/projects.js](src/data/projects.js) plus the two copy keys per project; card art goes in `src/Assets/Projects/`
- Experience, education, FAQ: locale files under `experience.*`, `education.*`, `faq.*`; the components only list keys. Each education entry also carries `t1..tn` tag chips rendered under its bullets. The three education entries are researched against primary sources in `docs/MATRICULATION.md`, `docs/DEGREE.md` and `docs/BOOTCAMP.md`, which are **gitignored on purpose and must stay that way**: this repository is public and those notes carry transcript grades, a capstone provenance finding and pointers to personal data in other repositories. Read them before touching any education copy; each has a Copy status section recording what shipped and a "Do not publish" list that is binding on any later edit. If they are missing from your checkout, ask rather than writing education copy from scratch
- Certifications and testimonials: the arrays at the top of [Certifications.jsx](src/components/About/Certifications.jsx) and [Testimonials.jsx](src/components/About/Testimonials.jsx) (dates as `YYYY-MM`); the Certifications heading also links the full list on LinkedIn, which backs the 100+ stat. Press mentions: `press` in `data/mytax.js`, only articles that name the MyTax mobile app itself (not only the web portal), each with the sentence that does so as `quote`; the Malay edition goes in `titleOriginal`, `urlOriginal` and `quoteOriginal`. Never describe a feature in the press as one Zariff built unless he says so
- Project cards: `coursework: "fyp" | "team"` in `projects.js` adds a university badge (`projects.fypBadge`, `projects.teamBadge`)
- Skills and tools: [Stack.jsx](src/components/About/Stack.jsx). Hardware and daily tools: [Uses.jsx](src/components/Uses.jsx), with notes localised under `uses.notes.*`
- Headline stats: [src/data/stats.js](src/data/stats.js). Install counts: `storeLinks` and `lifetimeInstalls` in `data/mytax.js` plus `store.*.count` and `home.proofInstallsValue` in both locale files, the meta descriptions in `index.html`, the headline stat's `aria-label` in `MyTaxCaseStudy.jsx`, and the summary and Zen bullet in `tools/resume/resume.html` (then rebuild the PDF); the App Store figure comes from App Store Connect, the other two from what each listing shows
- `public/sitemap.xml`: bump `lastmod` for the routes a change touches
- Resume: edit [tools/resume/resume.html](tools/resume/resume.html) (single column, real text, no letter-spacing, dates as "Mon YYYY to Mon YYYY"), then `node tools/resume/build.js` to regenerate `src/Assets/Zariff-Danial-Resume.pdf` and `node tools/resume/check.js` to confirm it still parses in reading order on one page. The build needs `playwright` (a devDependency; it uses the installed Chrome) and optionally `pdf-lib` for the PDF metadata step, which is not a project dependency; supply it via NODE_PATH or skip it. `check.js` reports the page count (one is the target, two the ceiling) and any parsing problems; it loads the ESM-only `pdfjs-dist/legacy/build/pdf.mjs` with a dynamic `import()`. The resume scripts are CommonJS because the package has no `"type": "module"`; `tools/qa/sweep.mjs` is ESM. Everything under `tools/` is excluded from lint. Bump `resume.lastUpdated` in both locale files.

Assets are imported as ES modules so Vite fingerprints them at build time; never reference them by URL string. The favicon and icon PNGs, `manifest.json`, `robots.txt`, `sitemap.xml` and `preview.jpg` stay in `public/` and are copied to `dist/` verbatim. The site shows no photo of Zariff: he asked for it to be taken off, so do not add one unless he asks (`src/Assets/me.png` is a local original that is gitignored). Phone screenshots (MyTax `pic N.jpeg`, Silent Support `silent-N.jpeg`, HalalSaji `halalsaji-1.jpeg`, the last captured from a web build of the app on its sample data with no certificate numbers on screen) have 300px variants (`pic N-300.jpeg`, `silent-N-300.jpeg`, `halalsaji-1-300.jpeg`) that `PhoneFrame` picks up through `srcSetFor()` in `data/screenshots.js`; regenerate both sizes and re-register if a screenshot changes. App icons (`public/icon-*.png`, `apple-touch-icon.png`, `favicon-32.png`) are rendered from the wordmark; `public/preview.jpg` is the Open Graph image, a 2400x1260 capture of the home hero.
